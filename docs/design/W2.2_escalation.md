# W2.2 — Escalation Module Design Contract

**Purpose.** This document pins every decision an implementer needs to build
`src/mentar/safety/escalation.py` and its tests **without re-opening a safety
judgment call**. The SAFETY.md Layer 3 prose, the FSM states, and the
`escalation_log` schema already exist; this is the engineering contract that
binds them together and makes the W2.2 acceptance criterion —
*"trigger→freeze→alert path demonstrated in a scripted test"* — mechanical to satisfy.

> **Scope boundary.** This is the **v0.1-interim** design. It is sufficient for the
> Phase-0 pilot (single vetted family, parent physically present, parent-mediated mode).
> It is **not** a final safeguarding policy. Bucket D research (SPEC §17.5) supersedes
> the trigger list and the two interim decisions in §6. See §7 rollout guard.

---

## 1. What is in scope for W2.2

| In scope (build now) | Out of scope (Bucket D / later W-task) |
|----------------------|----------------------------------------|
| Single-turn trigger classifier (keyword/regex, sensitivity-biased) | Multi-turn / escalating-distress pattern detection |
| Binary trigger → freeze (no gradation) | Gradated response levels (soft check-in before freeze) |
| Verbatim logging to `escalation_log` | ML classifier; validated keyword list from safeguarding pros |
| Fixed handoff message render (no LLM) | Handoff wording validated by a child-communication specialist |
| Parent-alert signal (on-screen flag + log row) | Phase-1 push notification, PIN gate |
| Interim decision on emergency signposting (§6.1) | Crisis-helpline signposting for unsupervised use |

## 2. Trigger taxonomy → stable `trigger_class` values

SAFETY.md §3.2 groups triggers into Categories A–D (human-readable). The **code and
the DB** use a stable lower-snake `trigger_class` string. This is the canonical map —
do not invent new strings; `escalation_log.trigger_class` stores exactly these.

| SAFETY.md category | `trigger_class` (stored) | Severity | Example signal |
|--------------------|--------------------------|----------|----------------|
| A — Physical safety | `harm_to_self` | critical | "I want to hurt myself", "I want to die" |
| A — Physical safety | `physical_danger` | critical | "someone is hurting me", "I don't feel safe at home" |
| B — Emotional/welfare | `severe_distress` | high | persistent despair / hopelessness beyond normal frustration |
| C — Safeguarding | `abuse_disclosure` | critical | grooming / sexual-abuse / exploitation disclosure |
| C — Safeguarding | `secrecy_request` | high | "don't tell my mum", "keep this a secret" |
| D — AI integrity | `adversarial_jailbreak` | low | jailbreak attempt (Layer 1 §1.4 blocks; logged here for audit) |

**Severity** is *recorded but not acted on differently* in v0.1 (binary freeze for all
A/B/C; D is logged-only — see §4.3). Severity exists so Bucket D has graded data later
and so the parent alert can sort by it. Do not branch flow on severity in v0.1.

## 3. Module API (`src/mentar/safety/escalation.py`)

Implement exactly these names. Pure, dependency-light, deterministic.

```python
from dataclasses import dataclass
from enum import Enum

class TriggerClass(str, Enum):
    HARM_TO_SELF        = "harm_to_self"
    PHYSICAL_DANGER     = "physical_danger"
    SEVERE_DISTRESS     = "severe_distress"
    ABUSE_DISCLOSURE    = "abuse_disclosure"
    SECRECY_REQUEST     = "secrecy_request"
    ADVERSARIAL_JAILBREAK = "adversarial_jailbreak"

class Severity(str, Enum):
    CRITICAL = "critical"
    HIGH     = "high"
    LOW      = "low"

@dataclass(frozen=True)
class TriggerMatch:
    trigger_class: TriggerClass
    severity: Severity
    matched_span: str        # the substring that fired (for the log/debug, NOT the alert)
    # NB: the FULL verbatim input is logged separately and never truncated.

def classify(text: str) -> TriggerMatch | None:
    """Single-turn classifier. Returns the HIGHEST-severity match, or None.
    Sensitivity-biased: when in doubt, fire. False positives are acceptable and
    expected (SAFETY.md §3.2); false negatives are not."""

# The constant the FSM/UI renders verbatim on entering ESCALATION_FREEZE.
# This is a FIXED STRING. It is never passed through the LLM. (SAFETY.md §3.4)
HANDOFF_MESSAGE_PRIMARY: str
HANDOFF_MESSAGE_SUPPORT: str
```

**Classifier rules (v0.1):**
- Case-insensitive, whitespace/punctuation-tolerant matching over a per-class keyword
  and regex bank. Keep the banks as module-level constants, one per `TriggerClass`,
  so Bucket D can swap them wholesale.
- **Precedence on multiple matches:** return the highest `Severity`; ties broken by the
  category order in §2 (A before B before C before D). The flow does not care which
  critical fired, but the log should record the most acute one.
- **No external calls, no model inference.** Deterministic so the scripted test is stable.
- Matching is **substring-aware but word-boundary-respecting** where it reduces obvious
  false positives that would erode trust (e.g. "die" inside "diet"/"died in the game"
  needs care) — but **bias still favours firing**. Document any boundary exception in a
  comment with its rationale; do not silently drop a Category-A keyword to cut noise.

**What `escalation.py` does NOT do:** it does not write to the DB, render UI, or manage
FSM state. It is a pure classifier + the fixed strings. Persistence and freeze are the
caller's job (the session loop / FSM driver), writing `escalation_log` per §4.

## 4. Flow contract (caller responsibilities)

The classifier is one half; the *demonstrable path* W2.2 requires is the caller wiring.
For the scripted test, the caller (or a thin `handle_trigger()` helper — implementer's
choice, but keep classification pure) MUST, on a non-None `classify()` result, in order:

1. **FREEZE** — suppress all tutoring output; transition FSM to `ESCALATION_FREEZE`
   (SESSION_FSM.md: absorbing state).
2. **LOG** — insert one `escalation_log` row: `learner_id`, `trigger_class` (the stored
   string from §2), `trigger_text_verbatim` = the **full, untruncated** child input,
   `freeze_started_at` (default now), `session_outcome='frozen'`, `parent_ack_at=NULL`.
3. **HANDOFF** — render `HANDOFF_MESSAGE_PRIMARY` + `_SUPPORT` exactly once. No LLM.
4. **ALERT** — surface the parent flag (pilot = on-screen flag in parent log view + the
   row marked ESCALATION). The alert carries timestamp + `trigger_class` only — **never
   the verbatim text** (that lives in the log, behind parent review). FSM:
   `alert_sent → PARENT_ACK_WAIT`.
5. **WAIT / RESUMPTION GATE** — no resume except explicit `parent_ack_resume`
   (→ `NODE_SELECT`, `session_outcome='resumed'`) or `parent_ack_end`
   (→ `SESSION_END_BY_PARENT`, `session_outcome='ended_by_parent'`). Set
   `escalation_log.parent_ack_at` on either.

### 4.3 Special case — `adversarial_jailbreak`
Category D is **logged-only**, not frozen. Layer 1 §1.4 already blocks the input inline;
the escalation log entry exists purely for audit. So: write the `escalation_log` row
(session_outcome stays e.g. `frozen`? **No** — use `session_outcome='logged_only'`) and
**do not** enter `ESCALATION_FREEZE`. This is the one place flow branches on class.
> Implementer note: confirm `session_outcome='logged_only'` is acceptable against the
> schema CHECK (the column is free TEXT today — fine). Add it to the schema comment.

## 5. T2.1 fixture taxonomy (the 20 + 20 the test must cover)

The scripted test (`tests/safety/test_escalation.py`) demonstrates the path and proves
the sensitivity bias. Build fixtures to this taxonomy so coverage is auditable.

**20 POSITIVE (must fire, asserts correct `trigger_class` + freeze):**
- 4 × `harm_to_self` (incl. one indirect: "I don't want to be here anymore")
- 4 × `physical_danger` (incl. one home-danger: "I don't feel safe at home")
- 3 × `severe_distress`
- 4 × `abuse_disclosure` (incl. one grooming-pattern, one euphemistic)
- 3 × `secrecy_request` ("don't tell my mum", "it's our secret")
- 2 × `adversarial_jailbreak` (asserts logged_only, NOT frozen — see §4.3)

**20 NEGATIVE (must NOT fire — protects the lesson from false freezes that erode trust):**
- 6 × on-topic math distress that is NORMAL frustration: "I hate fractions", "this is
  so hard I want to give up on this problem", "I'm dying of boredom" — must NOT freeze.
- 4 × curriculum content containing trigger-adjacent words innocently: "half *died* off"
  in a word problem, "cut the cake to *kill* the craving" — must NOT freeze.
- 4 × off-topic-but-benign: "can we play a game", "what's your favourite colour".
- 3 × ambiguous-but-below-threshold: mild "I'm a bit sad today" — **document the call.**
  v0.1 bias says: if it plausibly maps to `severe_distress`, FIRE. These cases pin where
  the line currently sits so Bucket D can move it deliberately.
- 3 × empty / whitespace / emoji-only input.

> The 6 + 4 "normal frustration / innocent content" negatives are the most important set:
> a tutor that freezes every time a child says "I hate this" is unusable. This is the
> precision floor the classifier must clear even while biased toward recall.

## 6. Interim safety decisions (Opus — the two load-bearing gaps)

These close the two SAFETY.md §3.5 / Appendix-B items flagged as **load-bearing gaps**.
They are *decided for the pilot* — not deferred — but each carries a rollout guard (§7).

### 6.1 Emergency-services signposting — DEFERRED for pilot, GUARDED for rollout
**Decision.** The pilot displays **no crisis-helpline / emergency numbers** to the child.
On any Category-A trigger the child is routed to the **physically-present parent** via the
fixed handoff message; the parent is the escalation target.

**Rationale.**
- Pilot runs only in parent-mediated mode with the parent physically present (SPEC §6.2,
  pilot constraint). A present, vetted adult is a more appropriate first responder for an
  ~8–9-year-old than a phone number the child reads alone.
- Showing crisis numbers to a young child *without* adult mediation is itself a
  child-communication risk we are not equipped to validate at v0.1.

**The hole this leaves (stated, not hidden).** "Route to the present parent" **fails when
the parent is the source of harm** — exactly the `physical_danger` ("not safe at home")
and `abuse_disclosure` cases. The pilot bounds this risk by vetting the single
participating family, but the design does **not** solve it. Therefore:

### 6.2 Handoff message — interim wording FROZEN for pilot, GUARDED for rollout
**Decision.** The SAFETY.md §3.4 wording is **frozen as-is** for the pilot and lives as
the `HANDOFF_MESSAGE_*` constants. No change required to ship the pilot.

**Rationale.** The wording is age-appropriate, non-alarming, and points to a human. It is
adequate for a supervised single-family trial.

**Outstanding (carried, not closed).** The wording has **not** been reviewed by a
safeguarding professional or child-communication specialist. That review remains required.

## 7. Rollout guard (do not lose this)

> **Both §6.1 and §6.2 are interim. Mentar MUST NOT move beyond the supervised
> single-family Phase-0 pilot — specifically MUST NOT enable independent/unsupervised
> mode or onboard additional families — until BOTH close:**
> 1. Emergency-services signposting decided with safeguarding input (covers the
>    parent-is-the-harm hole in §6.1), AND
> 2. Handoff wording validated by a safeguarding / child-communication professional.
>
> This guard mirrors the standing project note on the SAFETY §3.4/§3.5 gap and is the
> blocker on broader rollout until W2.2 fully closes (post-Bucket-D).
