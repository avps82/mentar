# Hybrid Content Architecture — Hand-Authored + Retrieval-Verified

## The question that surfaced this

The maintainer asked a practical question — "what's the minimal Khan Academy download for my
Year 8 kid?" — which led to discovering that **every non-pilot curriculum node had zero grounding
configured** (as of 2026-07-25: 29 templates, AU_ACARA/IN_GENERIC/practice, all years). All content in those
packs is generated by hand-authored parametric formulas or curated fact tables baked directly
into Python code — never extracted from a ZIM. Grounding (the ZIM/retrieval machinery this
project built substantial infrastructure for — W7, NIAH, the eval framework) is wired to exactly
one pack: the original 8-node Phase-0 pilot.

This led to a live empirical test of whether an LLM can be trusted to supply factual/technical
content (chemistry) directly from its own trained knowledge, ungrounded. **Confirmed no** — see
§3 below. That result is what shapes the decision in §1.

## 1. The decision (ratified by the maintainer)

**Neither architecture replaces the other. Use whichever fits the subject/grade, and build a real
hybrid — this is the direction, not yet the implementation.**

| | **Hand-authored** (current) | **Retrieve → extract → verify → freeze** (proposed) |
|---|---|---|
| **When to use** | Lower grades; any subject/topic with **no deviation** — stable, well-defined facts or a parametric formula that doesn't run out of variation (arithmetic, basic vocabulary, basic science classification) | Higher grades; subjects that need **source grounding and validation**, and where hand-construction + random parametric generation **runs out of variation** — the maintainer's own framing: "we will hit a problem where manual construction will get you so far and not much variation exists" |
| **Status** | **Proven** — shipped, 76 nodes audited (`docs/EXPLAIN_METHOD_AUDIT.md`), self-validated 300–3000 draws per generator, 0 failures | **Not built.** No retrieval-to-item pipeline exists anywhere in the codebase today |
| **Verdict** | Keep exactly as-is for the subjects it already covers well | Build for the subjects/grades where it's actually needed — not a wholesale migration |

The maintainer's own reasoning, stated plainly: hand-authoring "works for any lower grade
subject and it shows" and "will work for some higher grade subjects" too — this is not being
retired. It's being **scoped down** to where it's the right tool, with the retrieval-verify
path added **alongside** it for where it isn't.

## 2. Why "hybrid," not "replace" — the underlying invariant

Whichever path produces a given item, the runtime safety posture must stay identical to what's
already shipped for maths (`engine/arithmetic_steps.py`'s "computed ground truth, LLM never
decides correctness" — the same discipline `explain_check.py`'s verified-arithmetic-claims guard
exists to enforce): **the LLM never generates or narrates a fact live in front of a child, in
either architecture.**

- Hand-authored: a human types the fact once; it's correct by construction from then on.
- Retrieval-verified: a human/reviewer verifies an *extracted* fact against its source once; it's
  frozen from then on.

Both converge on the same shape at runtime — a static, pre-verified item served by the existing
`ItemGenerator`/`ItemBank` machinery. The retrieval-verify path is a different **authoring**
pipeline, not a different **runtime** trust model. This is why "hybrid" is coherent rather than
contradictory: the two architectures produce the same trusted artifact through different
front-ends.

## 3. Empirical evidence the decision rests on (live-tested, 2026-07-25)

Tested two local models directly (`tools/llm.sh`) on chemistry, ungrounded:

- **Fact recall** (benzene's formula, pyridine's formula): both `phi4-mini` (~3.8B) and
  `qwen3.5:2b` (~2B) answered correctly (`C6H6`, `C5H5N`). Common, well-documented facts are
  reliably known even by small models — unsurprising, they're ubiquitous in any training corpus.
- **Computation/reasoning** (balance `C6H6 + O2 -> CO2 + H2O`): `phi4-mini` landed on the
  **correct final equation** (`2 C6H6 + 15 O2 -> 12 CO2 + 6 H2O`, verified correct) while its
  shown intermediate reasoning was **internally inconsistent nonsense** — it narrated "twenty
  oxygen atoms... split into fourteen... and another sixteen" in the same sentence (14+16≠20,
  and neither number matches the correct equation's actual atom counts). **A correct final
  answer riding on fabricated working** — arguably worse than a wrong answer, since a child would
  see confidently-stated wrong arithmetic presented as valid chemistry reasoning.

This is the concrete version of the general LLM hallucination risk this project's maths
verifier already exists to prevent — it just hadn't been tested for a subject where the project
has no equivalent guard yet (there is no chemistry "verifier" of any kind today).

## 4. Open, unscoped questions for whoever picks this up

Not decided here — flagging so the next scoping pass doesn't have to rediscover them:

- **Which subject/grade pilots the retrieval-verify path first?** Not chosen. Year 11 Chemistry
  was the example that prompted this conversation, not a commitment.
- **What ZIM source has enough depth for the target grade?** Vikidia/Simple Wikipedia (the
  current pilot's sources) skew younger; senior-secondary chemistry likely needs full Wikipedia
  or Khan Academy — bigger, and coverage/quality would need spot-checking, not assumed.
  (Khan Academy is also CC BY-NC-SA — `docs/CONTENT_LICENSES.md` already flags this as fine for
  the local non-commercial pilot, not the future hosted tier.)
  Sized to the actual subject scope, not the full ~180GB dump — a subject-scoped Kiwix selection,
  if one exists with adequate depth (not verified from this sandbox — no internet access here).
- **What does "extract a checkable Q&A pair from a passage" actually look like?** This is a real,
  non-trivial engineering problem (turning prose into an unambiguous, verifiable question) —
  needs its own design pass, likely LLM-assisted extraction + a verification/cross-check step
  before anything reaches a static item bank, mirroring the self-validation discipline every
  existing generator already follows.
  - Note: for a subject like chemistry, fact-recall content ("what is the formula of X") fits
    this pattern directly, but **computation-style questions (balancing, stoichiometry) are a
    separate problem** — retrieval gives facts, not a guaranteed-correct calculator. Those would
    need either a real chemistry-computation algorithm (the `arithmetic_steps.py` precedent, but
    for chemistry) or explicit descoping until one exists.
- **Who/what does the verification step?** Human review, an automated cross-check against the
  source passage (e.g. substring/entity matching), or both — not decided.

## 5. Related, explicitly far-future idea (logged, not scoped)

The maintainer separately raised: **a "drop in any ZIM file and learn about that topic" feature**
— a user-supplied custom-knowledge mode, where a parent/learner adds their own ZIM (any topic,
not just the vetted curriculum sources) and the local LLM answers/teaches from it on demand.
Explicitly framed by the maintainer as **"far far future state"** — not this decision, not
scoped, not estimated. Distinct from §1-4 above (which is about curriculum-authoring pipelines);
this would be a runtime, ad-hoc retrieval feature. Recorded here only so it isn't lost, not as a
commitment.
