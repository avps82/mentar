# W1.2 — Eval Tooling Scan: Needle-In-A-Haystack

The maintainer asked: scan **needle-in-a-haystack (NIAH)**, *try to run it*, and decide whether it
fits our quality-testing criteria for **all** the major parts — and if not, look elsewhere.

This time I had network + pip in the sandbox, so this is a **hands-on** assessment, not a desk one.

## What I actually did (evidence)

- **Cloned** `github.com/gkamradt/needle-in-a-haystack` (v2.0.0, MIT licence).
- **Installed** into a venv on Python 3.13: `pip install -e ".[dev]"` → clean.
- **Ran end-to-end** with the built-in `fake` provider (no model/API key needed):
  `niah demo --fake` → 6-cell sweep (2 context lengths × 3 depths) completed, wrote
  `results.jsonl` with per-cell `context_length`, `target_depth_percent`, needle placement,
  `expected_answer`, `response`, deterministic `score`, and a `reconstruct` replay path.
- **Ran its test suite**: `pytest` → **209 tests, all pass**.
- **Confirmed vLLM compatibility**: the `openai` provider reads `base_url` from an env var
  (`client.base_url_env` in the model config) → it can target a local **vLLM**
  OpenAI-compatible endpoint directly.

So: it installs, runs, is healthy, is MIT, is modular/maintained, and works against our
local vLLM. The build is sound. The question is *coverage*.

## Fit against Mentar's W1.2 quality criteria

| Major part of our quality bar | NIAH fit | Notes |
|-------------------------------|----------|-------|
| **Retrieval / RAG grounding faithfulness** (does the model find & use the grounding passage at varying positions and context lengths?) | ✅ **Strong — its core job** | Exactly our "grounding-as-data" faithfulness need (SAFETY §1.5). Depth×length heatmap is the right signal. |
| **Hallucination / answer correctness on tutoring content** (right fractions answers; honest "I don't know") | ❌ Out of scope | NIAH scores *needle retrieval*, not subject-matter correctness. Needs our own T1 dataset + the deterministic verifier (`eval/verify_numeric.py`). |
| **Safety / adversarial / injection robustness** (jailbreaks, injected-passage attacks, distress deferral) | ⚠️ Partial / reusable | Not built for it — but a needle containing an *imperative-to-AI* ("ignore your instructions…") is a neat **injection-robustness probe** (does the model obey a planted instruction?). Doesn't cover jailbreak/distress; those stay in our T1 adversarial set + escalation tests. |
| **Child-appropriate output quality** (register, non-shaming, scope) | ❌ Out of scope | Our own eval / human review. |
| **Deterministic scoring** | ✅ | `exact_match` + `chain_match` scorers and uuid needles → no LLM-judge required. Good. |

## Verdict

**It fits ONE major part — retrieval/grounding-faithfulness — and fits it well. It is NOT a
complete W1.2 quality harness** (it covers ~1 of our ~4–5 dimensions). So:

- **ADOPT NIAH** as the *retrieval/long-context faithfulness* instrument of W1.2. Run each
  candidate model (Qwen2.5-7B, Llama-3.1-8B, Gemma-2-9B, Phi-4-mini, …) through a NIAH
  sweep against our local vLLM; low retrieval accuracy at our working context lengths is a
  disqualifier (a tutor that loses the grounding passage will hallucinate to a child).
- **Keep building our own T1 harness** for the parts NIAH does not cover: hallucination/
  correctness (T1.1 dataset + `verify_numeric`), safety/adversarial/injection (T1 adversarial
  set + escalation), child-appropriateness (human review). NIAH does not replace these.

**Answer to "does it fit all major parts?": No — but it's the right tool for the retrieval
part, and worth adopting for that rather than building our own retrieval harness.**

## How to run it against our vLLM (no secrets in files)

Ready config committed at `eval/niah/models/vllm.example.yaml`. Usage:

```bash
pip install needlehaystack
export MENTAR_VLLM_BASE_URL="http://localhost:8000/v1"
export MENTAR_VLLM_API_KEY="<dummy-or-real>"     # vLLM often accepts any token
niah run --config eval/niah/models/vllm.example.yaml   # (point run config at this model)
```

The `base_url_env`/`api_key_env` indirection means **no endpoint or key is written to a
file** — consistent with the secret safeguard (config/README.md).

## If we wanted a broader tool for the other parts (optional)

We mostly **build our own** (we already have the verifier, fringe, escalation, prompt
registry). If a framework is wanted later for the hallucination/safety dimensions:
- **RAGAS** — RAG faithfulness/answer-relevance scoring (complements NIAH's positional test).
- **promptfoo** / **DeepEval** / **lm-evaluation-harness** — general LLM eval harnesses with
  assertions, red-teaming, and matrix runs.
These are candidates only — not needed for G0; our own T1 + NIAH covers the pilot.
