# W2.2 — Emergency-services signposting

> ⚠️ **This is a child-safety policy question. I am not a safeguarding professional and this doc
> does not set policy.** It frames the options and what must be obtained from a qualified
> safeguarding / child-communication professional. Any helpline specifics below are **illustrative,
> pending professional validation** — do not ship them as-is.

## The situation (W2.2 §6.1)

Interim decision: on a Category-A trigger the child is routed to the **physically-present parent**
via the fixed handoff message; **no crisis/emergency numbers are shown to the child.** Rationale:
in a supervised, parent-mediated pilot the safe adult is right there.

**The stated hole:** "route to the present parent" **fails when the parent is the source of harm**
— exactly the `abuse_disclosure` / `physical_danger` classes. This is acceptable *only* under the
supervised single-family pilot, and is a hard blocker for unsupervised/independent mode
(SAFETY.md §3.5 rollout guard).

## Options

| Option | What | When appropriate |
|---|---|---|
| **A — Keep parent-route, no signposting (recommended *for the pilot only*)** | Status quo. The present, vetted parent is the escalation target. | The current supervised single-family pilot, with the rollout guard intact. **No change needed to ship the pilot.** |
| B — Child-facing crisis signposting | On Category-A triggers, show the child an age-appropriate trusted-adult / helpline message (region-aware). | Required **before** any unsupervised/independent mode. Needs professional wording + display-trigger rules. |
| C — Hybrid (targeted) | Parent-route for most classes; for `abuse_disclosure` / `physical_danger` specifically, show a child-facing trusted-adult/helpline message that does **not** assume the parent is safe. | The most defensible path for closing the hole; also needs professional sign-off. |

## Recommendation

- **For the pilot: ratify Option A**, keeping the SAFETY.md §3.5 rollout guard explicit (MUST NOT
  go beyond the supervised single-family pilot until signposting is designed).
- **Before broadening: commission a safeguarding professional** to design **B or C** — this is not
  something to author in-house.

## What's needed (so this can close properly)

1. **Your pilot decision:** confirm Option A for the supervised pilot (likely yes).
2. **Commitment:** obtain safeguarding-professional review to design B/C before unsupervised mode.
3. **Region scope** for any future helplines (pilot is GB → e.g. *Childline 0800 1111*, *999/112* —
   **illustrative only, must be validated**; other regions need their own resources).
4. The professional should specify: which `trigger_class`es show signposting, the exact wording
   (age-appropriate, non-alarming — runs through `safety/handoff_check.py`), and the parent-is-harm
   handling.
