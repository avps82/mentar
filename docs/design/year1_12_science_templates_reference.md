# Year 1-12 home-based science visual templates (2026-07-19)

Maintainer dump, LOGGED ONLY (same log-only pattern as the math template
rounds logged earlier the same session — no action requested, no build).
This is a NEW topic domain — SCIENCE, not maths — distinct from every other
"show human working" / math-templates memory logged so far. Nothing in this
project currently ships any science curriculum content at all (Phase 0 pilot
= fractions; shipped breadth is AU_ACARA/IN_GENERIC MATHS + some English,
see [[project_r14a_au_breadth]] / [[project_r15_partial_au_y78]]) — so unlike
some of the math template rounds (which mostly needed a visual for EXISTING
content), this entire domain needs curriculum content designed and built
FIRST, before any visual template is relevant.

10 templates across 4 sections, all using a distinctive "home appliance /
household object" framing (kettle, fridge, microwave, compost bin, potted
plant, door handle, consumer unit) rather than abstract diagrams — worth
noting as a deliberate pedagogical style choice if this ever gets picked up
(concrete, at-home objects a child can actually go look at, not abstract
textbook diagrams).

## Section 1: Kitchen chemistry & thermal dynamics

### Template 1 — the boiling kettle (states of matter & phase changes)

Tracks heat energy transforming water from liquid to gas, condensation on
windows/lids.

```text
           [ STEAM (Gas) ]  <-- Random, fast-moving particles
              \   ▲   /
               \  |  /  (Evaporation Phase Change)
            +--+--+--+--+

            |  ~~~~~~~  |
            |  ~~~~~~~  |  <-- [ WATER (Liquid) ] Fluid, loose particles
            +-----------+

            |===========|  <-- [ ELEMENT (Heat Input) ] Thermal Energy Source
```

### Template 2 — baking soda & vinegar volcano (chemical reaction kinetics)

Acid-base neutralization using household pantry items, gas production.

```text
               ( CO2 Gas Bubbles )
                  ( O )   ( O )
                   \         /
                    \       /

                     |     |
                     |     |   <-- Acid + Base Reaction Area
                    /       \      [Vinegar (Acid) + Baking Soda (Base)]
                   /         \
                  /___________\  ==► Product: Sodium Acetate + Water + CO2 ↑
```

### Template 3 — the refrigerator (thermal energy transfer / heat pump)

How a fridge pumps heat OUT of the cabin to keep food cold.

```text
            +-----------------------+

            |  [ FREEZER CAVITY ]   |
            |   Cold Air Circulates |
            |      │         │      |
            |      ▼         ▼      |   ==► Thermal energy is continuously
            |  [ FRIDGE CABIN ]     |       extracted from inside the box.
            +-----------------------+
                       │
                       ▼ [ HEAT EXPENDED ]
              (Warm air coils at back of fridge)
```

## What this would actually need if ever picked up

Unlike the math template rounds (mostly: "existing content just needs a
visual"), this is genuinely new ground for the project:

1. **Science curriculum content doesn't exist yet** — no science item bank,
   no science curriculum templates, nothing under `curriculum/templates/`
   for any science subject. This would need its own curriculum design pass
   (year-level scope, country/board alignment same as the maths packs,
   licensing check same as [[project_safeguarding_packet_and_us_licence]] /
   `docs/CONTENT_LICENSES.md`) before any template/visual work is relevant.
2. **These templates are largely qualitative/conceptual**, not "compute the
   right answer and show the steps" the way arithmetic is — a different
   verification posture is needed (there's no single deterministic
   "ground truth" answer to check the way `eval/verify_numeric.check` does
   for a division problem). Needs its own thinking on what "correct" even
   means for a diagram explaining photosynthesis.
3. **Section 5's tracking-matrix templates are a different SHAPE entirely**
   — closer to an interactive worksheet/calculator than a static
   explanatory diagram. If pursued, would likely want real input fields
   and a live calculation (matching the project's existing structured-widget
   pattern, e.g. the fraction numerator/denominator inputs in `_turn.html`),
   not a static rendered grid.
